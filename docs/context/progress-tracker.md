## Stage 02 project invitations - PR #7 (merged)

- From the merged PR #6 base, an active project owner can issue, inspect pending, and revoke seven-day invitations for an exact verified email and EDITOR, REVIEWER, or VIEWER role. The first successful issue returns a 256-bit one-time link; PostgreSQL stores only its SHA-256 hash. A matching idempotency retry returns safe metadata without reconstructing the link. Issuance is limited to 50 live pending invitations per project; the list is bounded to those pending invitations. Links are shared manually; this slice does not send invitation email.
- Acceptance uses verified Supabase Auth identity, exact normalized email, and a locked project transaction. It creates or reactivates bookkeeping workspace membership, adds project membership, updates the membership version and realtime epoch, and saves one audit event and receipt. The owner counts toward the ten-person project limit. A workspace membership alone gives no project read. Existing project members are not silently upgraded; authorized same-actor retries, concurrent same-key retries, and an accepted member revisiting an expired link recover the established result.

Switching projects clears the prior project's private Share state. `/invite/[token]` shows neutral details until accepted, carries only a validated invitation path through sign-in, signup, verification, and account switching, and replaces the token URL after acceptance. The proxy refreshes Auth cookies on invitation routes.
